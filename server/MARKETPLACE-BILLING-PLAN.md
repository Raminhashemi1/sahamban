# طرح پرداخت درون‌برنامه‌ای و اشتراک سهام‌بان

وضعیت: تعرفه و دوره‌ها توسط مالک تعیین شده‌اند؛ اتصال فروشگاه و تأیید عملیاتی هنوز انجام نشده است.

## تصمیم قطعی محصول

- پرداخت فقط درون‌برنامه‌ای و از طریق فروشگاه‌های مورد تأیید (مایکت و/یا کافه‌بازار) انجام می‌شود.
- اشتراک‌ها خرید یک‌باره با اعتبار ثابت هستند؛ تمدید خودکار و برداشت دوره‌ای ندارند.
- مبنای مدت، تعداد روز دقیق است؛ نه ماه تقویمی.
- واحد همه مبالغ **ریال (IRR)** است.
- خرید مجدد پیش از انقضا، روزهای جدید را به انتهای اعتبار فعال اضافه می‌کند.
- Pro فقط پس از اعتبارسنجی رسید توسط سرور و ثبت اتمیک entitlement فعال می‌شود.

## تعرفه مصوب مالک

| شناسه داخلی | مدت دقیق | قیمت نهایی |
|---|---:|---:|
| `SAHAMBAN_PRO_30D` | ۳۰ روز | ۱٬۵۰۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_60D` | ۶۰ روز | ۲٬۸۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_90D` | ۹۰ روز | ۴٬۰۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_180D` | ۱۸۰ روز | ۷٬۶۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_365D` | ۳۶۵ روز | ۱۴٬۶۰۰٬۰۰۰ ریال |

این شناسه‌ها کلیدهای داخلی کاتالوگ سرورند؛ Product ID واقعی هر مارکت باید جداگانه در پنل ناشر ساخته و به این کلید داخلی نگاشت شود. مبلغ دریافتی از کلاینت پذیرفته نمی‌شود.

## معماری و کنترل‌های الزامی

1. آداپتر native مستقل برای SDK رسمی هر مارکت؛ وب‌اپ به‌تنهایی SDK بومی فروشگاه را اجرا نمی‌کند.
2. شروع خرید با Product ID واقعی فروشگاه و ارسال purchase token/receipt به سرور احراز هویت‌شده.
3. اعتبارسنجی server-to-server از API رسمی فروشگاه؛ callback یا پیام موفقیت کلاینت سند پرداخت نیست.
4. تطبیق package/app، محصول، حساب، مبلغ/واحد، وضعیت خرید، شناسه تراکنش و عدم replay.
5. ثبت رخداد پرداخت، تسویه سفارش و افزایش روزهای entitlement در یک تراکنش اتمیک.
6. رسید تکراری، سفارش تکراری، حساب نامنطبق، مبلغ اشتباه، خرید لغوشده یا بازپرداخت‌شده نباید Pro را فعال کند.
7. بازیابی entitlement باید از حساب سرور انجام شود؛ حذف و نصب مجدد نباید روزهای معتبر را از بین ببرد.
8. لغو یا refund/chargeback باید مسیر مستقل و قابل ممیزی داشته باشد.
9. checkout تا تکمیل اتصال واقعی، تأیید سیاست فروشگاه، تست sandbox و استقرار امن خاموش بماند.

## وضعیت فعلی مخزن

- کاتالوگ داخلی و منطق محاسبه دوره به پنج پلن روزشمار و قیمت‌های مصوب تغییر داده شده است.
- تست‌های واحد، سفارش، settlement و SQLite برای پنج پلن به‌روزرسانی شده‌اند.
- Worker فعلی نمونه پایلوت است؛ پرداخت و checkout واقعی هنوز خاموش‌اند.
- adapter واقعی مایکت/بازار، نگاشت Product IDهای پنل، اعتبارسنجی رسید در محیط واقعی، refund و بازیابی روی دستگاه هنوز نیازمند تکمیل و آزمون‌اند.
- هیچ قیمت یا Product ID فروشگاهی از روی حدس ساخته نمی‌شود.

## موارد لازم برای تکمیل اتصال واقعی

- تأیید اینکه عرضه در هر دو فروشگاه انجام می‌شود یا فقط یکی از آن‌ها.
- Product IDهای ساخته‌شده در پنل مایکت و کافه‌بازار برای هر پنج پلن.
- تأیید رسمی نوع محصول یک‌باره مدت‌دار با سیاست جاری هر فروشگاه.
- اپ اندروید نهایی/package name و دسترسی امن به حساب توسعه‌دهنده.
- سرویس هویت تجاری و پایگاه داده خصوصی production.

کلید خصوصی، رمز پنل، کلید امضای برنامه، اطلاعات بانکی یا توکن محرمانه را در GitHub یا چت قرار ندهید؛ فقط در secret manager امن پیکربندی شوند.
