# طرح پرداخت درون‌برنامه‌ای و اشتراک سهمینو

وضعیت: بازار هدف فقط کافه‌بازار است. بازنویسی Billing V2 در شاخه آزمایشی انجام شده؛ اتصال تجاری، تنظیم محصولات و انتشار هنوز تکمیل نشده است.

## تصمیم محصول ثبت‌شده
- فروش فقط از طریق **کافه‌بازار** و داخل برنامه اندروید انجام می‌شود.
- آداپتر بومی از Poolakey و API اشتراک آن استفاده می‌کند؛ خرید یک‌باره و درگاه وب خارج از این پیاده‌سازی‌اند.
- پنج مدت اشتراک موردنیاز: **۳۰، ۶۰، ۹۰، ۱۸۰ و ۳۶۵ روز**.
- مبالغی که به کاربر نمایش داده می‌شود باید **تومان** باشد؛ هرگز برچسب ریال را به مبلغ تومان نزنید.
- قیمت مرجع از جزئیات محصولی می‌آید که بازار برمی‌گرداند. تبدیل ریال به تومان فقط با تقسیم دقیق بر ۱۰ مجاز است؛ اگر مقدار قابل تبدیل نباشد، قیمت نمایش داده نشود.
- اعتبار اشتراک فقط پس از تأیید سرور و ثبت پایدار entitlement فعال می‌شود.
- تاریخ انقضا و وضعیت تمدید از پاسخ معتبر بازار مرجع گرفته می‌شود؛ کلاینت حق ساختن یا تمدید محلی اعتبار را ندارد.

## کاتالوگ داخلی فعلی

این شناسه‌ها صرفاً کلید داخلی سرور هستند و Product ID واقعی بازار نیستند. قیمت‌های قدیمی ثبت‌شده در جدول زیر، تا تطبیق نهایی با قیمت و تنظیمات پنج محصول در پیشخوان بازار، قیمت قطعی قابل نمایش یا فروش محسوب نمی‌شوند.

|---|---:|---:|---:|

قیمت نهایی، نوع محصول، طول دوره و رفتار تمدید باید در پیشخوان بازار تأیید شود. هیچ SKU یا قیمت فروشگاهی نباید حدس زده شود.

## معماری و کنترل‌های الزامی

1. اتصال بومی اندروید به Poolakey با `subscribeProduct` و بازیابی با `getSubscribedProducts`.
2. ساخت سفارش سمت سرور با شناسه پلن داخلی؛ مبلغ ارسالی از کلاینت پذیرفته نمی‌شود.
3. تطبیق package name، SKU واقعی، شناسه سفارش/developer payload، توکن خرید و امضای RSA.
4. اعتبارسنجی رسید اشتراک از Developer API بازار در سرور؛ callback کلاینت به‌تنهایی مجوز فعال‌سازی نیست.
5. ثبت سفارش، entitlement و رویداد پرداخت به شکل اتمیک و idempotent.
6. بازیابی هر خرید با اعتبارسنجی مجدد سمت سرور؛ موجودی محلی بازار به‌تنهایی کافی نیست.
7. بررسی تمدید، لغو تمدید، انقضا، بازپرداخت و برگشت وجه؛ لغو تمدید به‌تنهایی نباید دسترسیِ قبلاً پرداخت‌شده را فوراً قطع کند.
8. رابط کاربری باید مدت، مبلغ به تومان، شرایط تمدید/لغو و شرایط بازپرداخت تأییدشده را پیش از خرید روشن نمایش دهد.
9. پرداخت تا عبور از تمام آزمون‌های فنی و تأیید صاحب محصول خاموش بماند.

## وضعیت فعلی مخزن

- کاتالوگ پنج‌پلنی، جدول‌های سفارش/دسترسی/رویداد، اعتبارسنجی سمت سرور بازار و مسیرهای gated در Worker اضافه شده‌اند.
- آداپتر Poolakey، کلاینت HTTPS و ارکستراسیون خرید/بازیابی در ماژول آزمایشی اندروید اضافه شده‌اند.
- تست‌های کاتالوگ، امضا، رسید بازار، تسویه، تمدید، idempotency و feature gate اضافه شده‌اند.
- ماژول خرید هنوز به صفحه قابل مشاهده PWA/اندروید و هویت تجاری واقعی کاربر متصل نشده است.
- شناسه بسته فعلی `ir.sahamban.pilot` آزمایشی است و شناسه نهایی بازار نیست.
- اجرای ساخت APK آزمایشی در GitHub Actions هنوز موفق اعلام نشده است.
- هیچ پرداخت واقعی یا آزمون روی دستگاه بازارمحور انجام نشده است.

## موارد لازم از صاحب محصول

1. اعلام package name نهایی که در پیشخوان بازار ثبت شده است.
2. ایجاد/اعلام پنج SKU واقعی بازار و تأیید اینکه هر کدام دقیقاً مدت هدف را پشتیبانی می‌کند.
3. تأیید قیمت نهایی هر پنج پلن به تومان و سیاست تمدید/لغو/بازپرداخت در پیشخوان بازار.
4. تنظیم کلید عمومی RSA متناظر با برنامه و شناسه/رمزهای OAuth بازار به‌صورت Secret در محیط Worker؛ اطلاعات محرمانه در چت یا GitHub ارسال نشود.
5. تعیین سرویس هویت واقعی کاربر و اتصال امن نشست آن به اندروید و Worker.
6. اعمال schema روی D1 آزمایشی/تولیدی با بازبینی migration و سپس اجرای آزمون‌های انتهابه‌انتها.

کلید خصوصی امضای APK، رمز پنل، اطلاعات بانکی و توکن‌های محرمانه نباید در GitHub یا چت قرار گیرند؛ فقط در محیط امن و Secret Manager پیکربندی شوند.
