# طرح پرداخت درون‌برنامه‌ای و اشتراک سهام‌بان

وضعیت: مالک فروش را فقط از طریق کافه‌بازار تأیید کرده است. تعرفه‌ها مشخص‌اند؛ اتصال عملیاتی و انتشار هنوز انجام نشده است.

## تصمیم قطعی محصول

- تنها فروشگاه مجاز برای خرید اشتراک: **کافه‌بازار**.
- آداپتر اندروید هدف: SDK رسمی Poolakey کافه‌بازار؛ مایکت و Google Play خارج از محدوده‌اند.
- اشتراک‌ها خرید یک‌باره با اعتبار ثابت هستند؛ تمدید خودکار و برداشت دوره‌ای ندارند.
- مبنای مدت، تعداد روز دقیق است؛ نه ماه تقویمی.
- واحد همه مبالغ **ریال (IRR)** است.
- خرید مجدد پیش از انقضا، روزهای جدید را به انتهای اعتبار فعال اضافه می‌کند.
- Pro فقط پس از اعتبارسنجی رسید نزد سرور و ثبت اتمیک entitlement فعال می‌شود.

## تعرفه مصوب مالک

| شناسه داخلی | مدت دقیق | قیمت نهایی |
|---|---:|---:|
| `SAHAMBAN_PRO_30D` | ۳۰ روز | ۱٬۵۰۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_60D` | ۶۰ روز | ۲٬۸۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_90D` | ۹۰ روز | ۴٬۰۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_180D` | ۱۸۰ روز | ۷٬۶۵۰٬۰۰۰ ریال |
| `SAHAMBAN_PRO_365D` | ۳۶۵ روز | ۱۴٬۶۰۰٬۰۰۰ ریال |

شناسه‌های بالا کلیدهای داخلی کاتالوگ سرورند، نه Product IDهای واقعی پنل کافه‌بازار. برای هر پلن باید محصول واقعی در پنل ناشر ساخته و نگاشت دقیق آن ثبت شود. مبلغ ارسالی کلاینت پذیرفته نمی‌شود.

## معماری و کنترل‌های الزامی

1. آداپتر native اندروید با SDK رسمی Poolakey کافه‌بازار؛ هیچ مسیر خرید مایکت یا پرداخت مستقیم وب وجود ندارد.
2. شروع خرید با Product ID واقعی کافه‌بازار و ارسال purchase token/receipt به سرور احراز هویت‌شده.
3. اعتبارسنجی رسید server-to-server از API رسمی کافه‌بازار؛ callback یا پیام موفقیت کلاینت سند پرداخت نیست.
4. تطبیق package/app، محصول، حساب، مبلغ/واحد، وضعیت خرید، شناسه تراکنش و عدم replay.
5. ثبت رخداد پرداخت، تسویه سفارش و افزایش روزهای entitlement در یک تراکنش اتمیک.
6. رسید تکراری، سفارش تکراری، حساب نامنطبق، مبلغ اشتباه، خرید لغوشده یا بازپرداخت‌شده نباید Pro را فعال کند.
7. بازیابی entitlement باید از حساب سرور انجام شود؛ حذف و نصب مجدد نباید روزهای معتبر را از بین ببرد.
8. مسیر refund/reversal و ممیزی رخدادها باید مستقل و قابل پیگیری باشد.
9. checkout تا تکمیل adapter واقعی، تأیید سیاست کافه‌بازار، تست sandbox و استقرار امن خاموش بماند.

## وضعیت فعلی مخزن

- کاتالوگ داخلی، قیمت‌ها و محاسبه دوره به پنج پلن روزشمار اصلاح شده‌اند.
- تست‌های واحد، سفارش، settlement و SQLite برای پنج پلن به‌روزرسانی شده‌اند.
- شاخه فعلی فقط پوسته WebView آزمایشی دارد؛ کد adapter بومی Poolakey در این شاخه وجود ندارد. فایل آزمون قرارداد Poolakey به‌تنهایی پیاده‌سازی خرید نیست.
- Worker نمونه پایلوت است؛ checkout و پرداخت واقعی خاموش‌اند.
- اعتبارسنجی رسید واقعی کافه‌بازار، refund/reversal و بازیابی روی دستگاه هنوز پیاده‌سازی و آزمون نشده‌اند.
- هیچ Product ID یا قیمت فروشگاهی از روی حدس ساخته نمی‌شود.

## موارد لازم برای تکمیل اتصال واقعی

- پنج Product ID واقعی ساخته‌شده در پنل توسعه‌دهنده کافه‌بازار.
- تأیید نوع محصول و سیاست جاری کافه‌بازار برای فروش یک‌باره با مدت دسترسی ثابت.
- package name نهایی و نسخه امضاشده اپ که در کافه‌بازار ثبت می‌شود.
- دسترسی امن سرور به API رسمی اعتبارسنجی خرید کافه‌بازار و secretهای مربوط، فقط از طریق secret manager.
- سرویس هویت تجاری و پایگاه داده خصوصی production.
- آزمون sandbox روی دستگاه واقعی و تأیید بازیابی، refund و replay.

کلید خصوصی، رمز پنل، کلید امضای برنامه، اطلاعات بانکی یا توکن محرمانه را در GitHub یا چت قرار ندهید؛ فقط در secret manager امن پیکربندی شوند.
